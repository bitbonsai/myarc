# Boosts Phase B1 (Appearance) Architecture and Implementation Plan

Date: 2026-11-25
Spec: [docs/BOOSTS.md](../docs/BOOSTS.md)
Status: Proposed for review before implementation

## Goal

Deliver Boosts Phase B1: site-scoped colors, typography and scale, custom CSS, simple element hiding, live preview, reset, per-Boost toggle, and a global kill switch. Keep all Boost styling pure CSS with zero page JavaScript, strict Profile and private-browsing isolation, and no remote CSS network fetches.

## 1. Crate, Service, and Persistence Architecture

### Rust core: `crates/boosts`

Create a new dependency-free, safe Rust crate `crates/boosts` (`myarc-boosts`, `#![forbid(unsafe_code)]`), added to workspace `Cargo.toml` and symlinked into Chromium at `browser/foundation/boosts -> ../../crates/boosts` (matching `workspace`, `control`, and `import`). Add `rust_static_library("boosts")` in `browser/foundation/BUILD.gn` and expose its bounded records through `browser/foundation/bridge.rs`.

### Profile-scoped storage: `myarc-boosts-v1.json`

Store Boosts in a dedicated file per Profile (`<profile_dir>/myarc-boosts-v1.json`) rather than inside `myarc-workspace-v1.json`. This keeps workspace metadata small on every tab switch, isolates Boost file corruption from workspace recovery, and mirrors `WorkspaceService` cleanly.

- **Service**: `BoostsService` (`browser/foundation/boosts_service.{h,cc}`), `base::SupportsUserData::Data` keyed on exact `Profile&`, UI-sequence only.
- **Crash-safe atomic persistence**: Reuse `workspace::store` (`write`, `sync`, `backup_path`, `set_aside`) through `bridge.rs`. Each committed save writes synchronously to `<file>.tmp`, links the previous generation to `<file>.bak`, and atomically renames over `<file>`. An off-thread sequenced I/O task then runs `sync_all()` on the file and parent directory. On a damaged or torn file at startup, `BoostsService` sets the damaged file aside as `<file>.corrupt` and restores `<file>.bak`. Unsupported newer schema versions fail read-only without overwriting the file.
- **Off-the-record isolation**: `BoostsService::ForProfile` never redirects to `GetOriginalProfile()`. Incognito and Guest Profiles receive an ephemeral, empty `BoostsService` by default, so regular-Profile Boosts never apply in private browsing.
- **Live preview without disk churn**: Slider drags, color picking, and typing in the CSS box push transient preview CSS to the active tab's observer in memory. Disk writes happen on commit (blur, popover close, toggle, reset, delete, or explicit Save).

## 2. Rust Data Model, Validation, and CSS Sanitization

### Schema (`SNAPSHOT_VERSION = 1`)

```text
BoostsSnapshot {
  version: u32,
  global_enabled: bool,
  boosts: Vec<Boost>,
  next_boost_id: BoostId, // u64, monotonic, never reused
}

Boost {
  id: BoostId,
  name: String,                 // trimmed, no controls, <= 128 UTF-8 bytes
  origins: Vec<String>,         // 1..=16 normalized http(s) origins, no wildcards
  include_subdomains: bool,     // default false
  apply_to_subframes: bool,     // default false
  enabled: bool,                // default true on create; forced false on import
  version: u32,                 // increments on each committed edit
  updated_secs: u64,
  appearance: BoostAppearance,
  hidden_selectors: Vec<String>,
  custom_css: String,
  script_payload: Option<String>, // B3 reserved; ignored and never executed in B1
  revisions: Vec<BoostRevision>,  // bounded ring, <= 10 entries
}

BoostAppearance {
  color_mode: ColorMode,         // None | Invert | Palette (3 lighting mode toggles)
  palette: Option<BoostPalette>, // background, text, accent (0xRRGGBB), contrast (0..=100), tint_strength (0..=100)
  font: FontPreset,              // Default + 15 local system font stacks (4x4 Aa grid, 16 presets)
  text_scale_pct: u16,           // 50..=200, default 100
  text_transform: TextTransform, // None | Uppercase | Lowercase | Capitalize
}
```

### Hard Bounds

- `MAX_BOOSTS = 256` per Profile
- `MAX_ORIGINS_PER_BOOST = 16`, `MAX_ORIGIN_BYTES = 256`
- `MAX_HIDDEN_SELECTORS = 128`, `MAX_SELECTOR_BYTES = 256`
- `MAX_CUSTOM_CSS_BYTES = 65_536` (64 KiB)
- `MAX_SCRIPT_PAYLOAD_BYTES = 65_536` (64 KiB, inert in B1)
- `MAX_REVISIONS = 10` per Boost
- `MAX_FILE_BYTES = 8 * 1024 * 1024` (8 MiB) on JSON decode, `kMaxJsonDepth = 10`

### Origin Validation and Matching

The browser canonicalizes URLs with `url::Origin` / `GURL` before crossing the Rust boundary; Rust enforces the same invariants on mutation and decode:

- Allowed schemes: `http` and `https` only. Reject `chrome://`, `chrome-untrusted://`, `chrome-extension://`, `devtools://`, `file://`, `about:`, `data:`, `blob:`, `javascript:`, `view-source:`, opaque origins, credentials (`user@host`), paths, queries, fragments, and wildcards (`*`).
- Exact match by default: scheme, ASCII host, and effective port must all match.
- Subdomain match (`include_subdomains = true`): matches exact host or `<label>.<host>` on the same scheme and port. Rejects look-alike hosts (`notexample.com`, `example.com.evil.test`).

### CSS Sanitization and Remote-Resource Policy

Per `docs/BOOSTS.md`, CSS can trigger network fetches or leak page data via `@import`, `url()`, `image-set()`, `src()`, or `@font-face`. `crates/boosts` includes a single-pass, O(n) CSS lexer/sanitizer (no regex crate, no unsafe) that handles comments, strings, CSS hex escapes (`\75 rl(...)`), and nested parentheses:

1. **Block `@import`**: Any `@import` at-rule is rejected with a structured error (line and reason) and stripped during compilation as defense-in-depth.
2. **Restrict `url(...)`, `src(...)`, and `image-set(...)`**: Reject any remote, scheme-relative, relative, `data:`, `blob:`, `file:`, or `chrome:` URL. Allow only fragment-only local SVG references (`url(#id)`).
3. **Typography**: Font presets map strictly to local system font stacks (`-apple-system`, `ui-serif`, `ui-monospace`, `ui-rounded`, etc.). Remote webfont loading is disallowed in B1.
4. **Hidden selectors**: Each entry in `hidden_selectors` must be non-empty, <= 256 bytes, contain no control characters, and contain no `{`, `}`, `;`, `@`, or `/*` tokens so a selector cannot break out into arbitrary rules.
5. **Safe compilation**: `compile_boost_css(boost)` emits one bounded stylesheet containing:
   - `:root` and `html, body` appearance overrides when non-default.
   - `<selector> { display: none !important; }` for each validated hidden selector.
   - Sanitized `custom_css`, with any unclosed string or comment closed safely so concatenated Boosts cannot corrupt each other.
6. **Import safety**: Imported Boosts load with `enabled = false`, never run `compile_boost_css` during preview/import, and surface any blocked `@import` or remote `url()` findings in the inspection UI.

## 3. Chromium C++ Injection Mechanism

### Mechanism Choice: Blink `WebDocument::InsertStyleSheet` via `ChromeRenderFrame` Mojo

`content::RenderFrameHost` has no built-in `InsertCSS` API. Instead, Blink exposes keyed stylesheet injection directly on `blink::WebDocument` (`third_party/blink/public/web/web_document.h`):

- `WebDocument::InsertStyleSheet(source_code, &key, WebCssOrigin::kAuthor, BackForwardCacheAware::kAllow)`
- `WebDocument::RemoveInsertedStyleSheet(key, WebCssOrigin::kAuthor)`

**Critical Blink detail verified in `StyleEngine::InjectSheet` (`third_party/blink/renderer/core/css/style_engine.cc`)**: `InjectSheet` always appends to `injected_author_style_sheets_` and does not replace an existing entry with the same key. Therefore, the renderer handler must always call `RemoveInsertedStyleSheet(key, kAuthor)` before calling `InsertStyleSheet(...)` when updating a key.

**Why this beats alternatives**:
- **Pure CSS, zero page JS**: Avoids `ExecuteJavaScript`, isolated worlds, and CSP script-eval issues.
- **No page-to-browser bridge**: One-way browser-to-renderer Mojo push on the existing `chrome.mojom.ChromeRenderFrame` associated interface (already used by `browser/foundation/control_tabs.cc`).
- **Instant live preview and removal**: Updating or clearing CSS triggers a local Blink style recalc with no reload.
- **BFCache compatible**: `BackForwardCacheAware::kAllow` keeps Back/Forward Cache working.
- **Minimal upstream patch**: One Mojo method on `chrome/common/chrome_render_frame.mojom`, its implementation in `ChromeRenderFrameObserver` (~25 lines), and one attachment call in `chrome/browser/ui/tabs/tab_features.cc`.

### Renderer Contract (`ChromeRenderFrameObserver`)

Add one method to `chrome.mojom.ChromeRenderFrame`:

```mojom
SetBoostStyleSheet(string key, string css);
```

- Maintain a small `std::set<std::string> active_boost_keys_` per `ChromeRenderFrameObserver`, cleared in `DidCreateNewDocument()`.
- On `SetBoostStyleSheet(key, css)`:
  1. If `key` is in `active_boost_keys_`, call `doc.RemoveInsertedStyleSheet(WebStyleSheetKey(key), WebCssOrigin::kAuthor)` and erase `key`.
  2. If `!css.empty()`, call `doc.InsertStyleSheet(WebString::FromUTF8(css), &web_key, WebCssOrigin::kAuthor, BackForwardCacheAware::kAllow)` and insert `key`.

### Browser-Side Lifecycle (`BoostsTabHelper`)

`BoostsTabHelper` (`browser/foundation/boosts_tab_helper.{h,cc}`) is a `content::WebContentsObserver` + `WebContentsUserData` attached in `TabFeatures::Init(TabInterface&, Profile*)`. It subscribes to `BoostsService::ForProfile(*profile)`.

| Event / Case | Behavior |
| --- | --- |
| Cross-document navigation & reload (`DidFinishNavigation`, committed, non-error) | Check committed `RenderFrameHost::GetLastCommittedOrigin()` (post-redirect). If HTTP(S), not OTR, and `global_enabled`, compile matching Boosts and send `SetBoostStyleSheet("myarc-boosts", css)`. Otherwise send `""` if previously applied. |
| SPA navigation (`IsSameDocument()`) | Document persists, so the injected sheet stays active automatically; re-verify origin match and sync if preview/state changed. |
| BFCache restore (`IsServedFromBackForwardCache()`) | Re-sync all frames in the restored page with current `BoostsService` state so edits or disables made while cached apply immediately. |
| Redirects | Evaluated strictly against the final committed origin, never the initial request URL. |
| Subframes (`!IsInPrimaryMainFrame()`) | Skipped by default. When a matching Boost has `apply_to_subframes = true`, inject into same-origin subframes (or cross-origin subframes whose own origin explicitly matches a Boost with `apply_to_subframes = true`). |
| Privileged / internal schemes | Browser-side gate rejects all non-HTTP(S) and opaque origins before IPC. |
| Live preview / edit / disable / global kill switch | `BoostsService` notifies all `BoostsTabHelper` instances in that Profile; each iterates live frames via `WebContents::ForEachRenderFrameHost` and pushes the updated CSS (or `""`). |

*Note on FOUC*: `DidFinishNavigation` runs immediately on commit. If testing reveals visible unstyled flash on slow pages, a targeted follow-up can pre-send CSS in `ReadyToCommitNavigation` and apply it in `ChromeRenderFrameObserver::DidCreateNewDocument()` using the same Mojo channel.

## 4. Native UI Entry Points

### Library `Boosts` Section (`browser/foundation/library_view.cc`)

- Remove `Section::kBoosts` from the unbuilt guard in `IsBuilt()` and enable the search field for `Section::kBoosts`.
- Add `BoostPresentation` and delegate methods (`GetBoosts`, `ToggleBoost`, `OpenBoostEditor`, `DeleteBoost`, `SetAllBoostsEnabled`, `AllBoostsEnabled`) on `SidebarView::Delegate`.
- Pane layout (matching Arc Library -> Boosts):
  - Search field ("Search Boosts..."), matching Downloads and Archived Tabs.
  - Header bar with a global **Boosts On / Off** kill switch for the current Profile.
  - Scrollable list of Boost rows: rounded-square site favicon tile (dimmed with a diagonal slash overlay when disabled), Boost title ("My Boost"), host subtitle (`fly.io`, `news.ycombinator.com`, `www.npmjs.com`), enabled switch, click to open the origin and open the editor, context menu (Edit, Reset, Delete).
  - Empty state when the Profile has no Boosts (or no search matches).

### Per-Site Boost Editor Popover (`browser/foundation/boost_editor_view.{h,cc}`)

Native Views floating right-edge editor card (`BubbleDialogDelegateView`, following `SpaceThemePickerView` and `glass_mac` conventions and matching Arc's floating Boost card):

- **Entry points**:
  1. Site Info popover (`chrome/browser/ui/views/page_info/page_info_main_view.cc`, beside `CreateBlockerSwitchRow`): "Boost this site" / "Edit Boost..." row with quick toggle when a Boost exists for the current origin.
  2. Sidebar URL bar control (`kBoostsIcon`) on eligible HTTP(S) pages, highlighted when a Boost is active.
  3. macOS `View` menu (`command_ids.h`, `main_menu_builder.mm`, `browser_command_controller.cc`): `New / Edit Boost for This Site...` (`IDC_MYARC_EDIT_BOOST`) and `Disable All Boosts` (`IDC_MYARC_TOGGLE_BOOSTS`).
- **Controls inside the floating card**:
  - **Header**: Close `x`, title dropdown (`My Boost v`, with inline rename, read-only origin scope badge, "Include subdomains" toggle, Enabled switch, Undo, Delete), and Reset `↺` button.
  - **2D Color / Contrast Pad & 3 Lighting Modes**: Draggable 2D color/contrast pad above 3 mode toggle buttons (Invert/lightbulb, Sliders/palette, Clear/reset) driving live preview.
  - **Typography & Scale**: 4x4 `Aa` typography preset grid (16 local system font stacks), followed by side-by-side `Size` (50% to 200%) and `Case` (`None` / `Uppercase` / `Lowercase` / `Capitalize`) buttons.
  - **Zap (Element Hiding)**: Full-width `Zap` button (lightning icon) for click-to-hide (Slice 6) plus expandable list of hidden selectors with one-click restore (`x`), Clear All, and direct CSS selector input.
  - **Code (Custom CSS)**: Full-width `Code {}` button opening the monospace CSS editor, byte counter (`N / 64 KB`), and inline warning banner when the sanitizer blocks `@import` or remote `url()`.
- **Private windows & internal pages**: Entry points are disabled on non-HTTP(S) pages. In Incognito/Guest windows, the Site Info row explains that Boosts are disabled in private windows by default.

### Zap Element Picker (Slice 6, Pure C++ / Zero Page JS)

`docs/BOOSTS.md` lists simple element hiding in B1 and the full selector picker in B2. To keep B1 fast to ship while giving a clean path to interactive Zap:

- Slices 1 through 5 deliver complete B1 element hiding via `hidden_selectors` (add, live-preview, remove, reset, persist across reload and SPA navigation).
- Slice 6 adds an optional renderer-native Zap picker via a one-shot Mojo method `PickBoostElement() => (string? selector)` on `ChromeRenderFrame`: `ChromeRenderFrameObserver` uses Blink's C++ `HitTestResult` and a deterministic C++ selector builder (preferring `#id`, stable tag+class, or bounded `nth-of-type` path) with a native highlight overlay, cancelled by `Esc`. No page JS runs, and the returned selector still passes Rust's selector validator before saving.

## 5. Verification Plan and Acceptance Gates

### Unit Tests (`cargo test -p myarc-boosts --locked`)

- Origin matching: exact origin, port/scheme mismatch, subdomain match, look-alike host rejection (`notexample.com`, `example.com.evil.test`), blocked internal/privileged schemes.
- CSS sanitizer: `@import`, `url(http://...)`, `url(https://...)`, `url(//...)`, `url(data:...)`, `image-set(...)`, CSS escape bypasses (`\75 rl(...)`), comments inside tokens (`/*x*/url(...)`), uppercase `URL(...)`, unclosed comments/strings; allows safe rules and `url(#id)`.
- Bounds & recovery: >256 Boosts, >16 origins, >128 selectors, >64 KiB CSS, selector breakout (`} body { color: red }`), malformed/corrupt snapshots, unsupported future schema version.
- Revisions & import: undo restores prior revision, ring caps at 10, imported Boosts stay disabled and inert.

### C++ Bridge & Storage Check (`bridge_check`)

- `BoostsSnapshot` round-trip across `bridge.rs`, JSON decode limits, atomic save + `.bak` fallback + `.corrupt` set-aside.

### Synthetic Browser Fixtures (`tests/fixtures/browser/`)

Local HTTP test server fixtures verifying every acceptance example in `docs/BOOSTS.md`:

1. **SPA + reload + reversible hide**: Apply color/font/scale preset and hide an element -> verify computed styles and `display: none` -> reload -> SPA `history.pushState` navigation -> verify persistence -> disable Boost -> verify original layout and computed styles return immediately without reload.
2. **Origin & look-alike isolation**: Style origin A (`http://127.0.0.1:<portA>`); verify origin B (`http://127.0.0.1:<portB>`) and a look-alike hostname remain unstyled.
3. **Profile, OTR, and internal page isolation**: Style origin in Profile A; verify Profile B, an Incognito window, and `chrome://settings` are unaffected.
4. **Malformed CSS / selector recovery**: Save broken CSS syntax and an invalid selector; verify zero crash, intact settings, and clean recovery on disable/reset.
5. **Remote CSS zero-fetch canary**: Preview, import, and attempt to apply a Boost containing `@import url(http://127.0.0.1:<port>/canary.css)` and `background: url(http://127.0.0.1:<port>/canary.png)`; assert the local server receives zero requests to `/canary.*`.
6. **Global kill switch**: Toggle `Disable All Boosts` on a styled page; verify immediate reversion; re-enable and verify styles return.

## 6. Slice-by-Slice Implementation Order

1. **Slice 1 (Off-Chromium, Rust worktree)**: Create `crates/boosts` (`Cargo.toml`, model, origin matcher, CSS sanitizer, CSS compiler, revisions, unit tests) and symlink `browser/foundation/boosts -> ../../crates/boosts`.
2. **Slice 2 (Chromium lane)**: Wire `crates/boosts` into `browser/foundation/BUILD.gn` and `bridge.rs`; implement `BoostsService` (`boosts_service.{h,cc}`) with `myarc-boosts-v1.json` atomic persistence and OTR isolation; add `bridge_check` tests.
3. **Slice 3 (Chromium lane)**: Add `SetBoostStyleSheet` to `chrome_render_frame.mojom` and `ChromeRenderFrameObserver`; implement `BoostsTabHelper` (`boosts_tab_helper.{h,cc}`) and attach in `TabFeatures::Init`; wire global kill switch (`IDC_MYARC_TOGGLE_BOOSTS`).
4. **Slice 4 (Chromium lane)**: Enable `Section::kBoosts` in `LibraryView`, wire `SidebarView::Delegate` Boost actions, search, per-Boost toggle/delete, and global kill switch.
5. **Slice 5 (Chromium lane)**: Build `BoostEditorView` popover (colors, font/scale, hidden selectors list, custom CSS editor with sanitizer banner, live preview, reset, undo) and wire entry points in Page Info, sidebar URL bar, and `View` menu.
6. **Slice 6 (Chromium lane, optional B1.5 / B2 handoff)**: Add renderer-native C++ Zap element picker (`PickBoostElement` Mojo + Blink `HitTestResult`, zero page JS) connected to the editor's Zap button.
7. **Slice 7 (Verification)**: Add synthetic browser fixtures covering SPA, reload, origin/Profile/OTR isolation, remote-URL zero-fetch canary, malformed CSS recovery, and global kill switch, plus background native captures (`tools/capture_native.sh`).
